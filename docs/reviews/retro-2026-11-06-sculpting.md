# Разбор проверки лепки, 6 ноября 2026

Нативный прогон выявил пропуск мыши через полностью прозрачные пиксели окна. Проверка ignoresMouseEvents и координат callbacks этого не обнаруживала. Фон с альфой 2% дал захват всей области режима, повторный прогон подтвердил отмену без клика по нижележащей кнопке.

Обычная расчистка курсором продолжала выполняться во время лепки и уничтожала тонкий сугроб перед нажатием. Контроллерные тесты, вызывавшие только callbacks панели, обходили шаг симуляции. Добавлен тест с настоящим шагом между включением режима, движением и отпусканием. Он воспроизвёл потерю снега и отсутствие шара, затем подтвердил исправление и возврат расчистки после завершения.

При отключении курсора освобождение поддержки стен оставлено безусловным: одна коллекция heldLayers используется обоими механизмами. Это обнаружено независимым ревью.

Для нативного жеста нужен видимый снег в начальной точке. Полка Dock может иметь пустые участки, движение по ним корректно отменяет режим. По неуспешному жесту без видимого предварительного шара нельзя делать вывод о подтверждении транзакции.

Существующих правил проверки реального пути событий и воспроизведения перед исправлением достаточно. Изменений общих инструкций не требуется.


## Продолжение приёмки, 22:18 MSK

Тестовую программу сначала запустили через `open`, где её проверки вернули `AX=false capture=false`. Прямой запуск из текущего терминала вернул `AX=true capture=true`. Перед прогоном требуется проверять фактические права процесса, а не выводить их из подписи приложения.

Программа отправляла глобальные CGEvent и переключала окна, пока пользователь продолжал работать. Это нарушило условия проверки и мешало пользователю. По его замечанию глобальный ввод остановлен, профиль восстановлен. Существующих правил Cua Driver о сохранении фокуса и общем рабочем столе достаточно. Менять общие инструкции не требуется, нужно соблюдать их при выборе способа проверки.

## Автоматическая лепка и инерция

Пользователь заменил ручной режим на обычное движение указателя, затем добавил расталкивание снега при падении. Требования записаны в отдельную спецификацию. Проверки воспроизвели обход блокировки кликом, остановку опроса тонкого снега и одинаковую силу большого шара/снеговика из-за раннего ограничения массы. Эти случаи закрыты регрессионными тестами.

Для восстановления профиля defaults import оказался недостаточным: он объединяет ключи и оставляет временные значения, отсутствующие в резервной копии. Полная замена persistent domain восстановила точное состояние, проверено равенством словарей. Общие инструкции не меняются, способ восстановления записан в отчёте проекта.

## Рост маленького снежка

Проверки радиусов и массы не описывали время обычного движения. Интеграционные тесты перемещали указатель на 140 pt за один кадр и ожидали максимальный шар. Предпросмотр при этом рисовал минимальный радиус даже без необходимой массы. Обратная связь пользователя выявила, что такой сценарий мешает создавать маленькие снежки и показывает шар при первом касании.

Для этой правки проверяются последовательности кадров с реальной длительностью движения, отсутствие раннего предпросмотра и фиксация маленького размера по паузе. Расход снега должен соответствовать видимому радиусу. Параметры задержки и роста выбраны для SeasonArt, точные параметры эталона не измерены.
